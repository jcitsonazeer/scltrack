# Laravel Project Development Rules

## 1. General Rules
- Understand the existing project structure before making changes.
- Do not modify existing logic unless explicitly requested.
- Do not delete existing features.
- Write beginner-friendly Laravel code.
- Follow existing coding conventions.

## 2. Database Rules
- Do not delete or rename existing database tables.
- Do not delete or rename existing database columns.
- Do not delete existing database records.
- Do not modify existing migrations unless explicitly requested.
- Create new migrations when new database changes are required.

## 3. Laravel Backend Rules
- Follow Laravel MVC architecture.
- Keep controllers clean.
- Use service classes when appropriate.
- Validate all incoming API requests.
- Use proper HTTP status codes and JSON responses.
- Avoid unnecessary dependencies.

## 4. Frontend Rules
- Preserve the existing UI and design.
- Do not change existing CSS or layouts unless requested.
- Make only the requested frontend changes.

## 5. Before Making Changes
- Inspect the relevant files first.
- Explain the planned changes.
- Modify only the files necessary for the requested task.
- Check for errors after completing the changes.
- Summarize all modified files and changes.
